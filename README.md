# Tid 릴리스

Tid는 IT·AI 뉴스와 GitHub 인기 저장소를 모아 대시보드와 Slack 리포트로 정리하는 macOS 데스크톱 앱입니다.
이 저장소는 **배포 파일만** 둡니다. 소스 코드는 비공개 저장소에 있습니다.

## 설치

1. [최신 릴리스](https://github.com/xivicWon/tid-releases/releases/latest)에서 `Tid_<버전>_aarch64.app.tar.gz`를 받습니다 (Apple Silicon Mac).
2. 압축을 풀고 `Tid.app`을 `/Applications`로 옮깁니다.
3. 처음 열 때 macOS 확인 창이 나오면 Finder에서 우클릭 → **열기**를 누릅니다. Apple 공증을 받지 않은 앱이라 한 번은 이렇게 열어야 합니다.

## 업데이트

설치한 뒤에는 앱이 스스로 새 버전을 확인합니다 (시작 1분 뒤, 그 뒤 24시간마다).

- 새 버전이 있으면 상단 바 설정 아이콘에 점이 붙고, 설정 화면 "버전" 줄에 설치 버튼과 릴리스 노트가 나옵니다.
- 바로 확인하려면 설정의 "업데이트 확인" 또는 메뉴 막대 아이콘의 "업데이트 확인…"을 누릅니다.
- 설치는 사용자가 누를 때만 합니다. 진행 중인 수집이 끝난 뒤 설치하고 앱을 다시 시작합니다.

앱은 이 저장소의 `releases/latest/download/latest.json`을 읽고, 내려받은 파일의 서명을 앱에 들어 있는 공개 키로 확인한 뒤에만 설치합니다. 서명이 맞지 않으면 설치하지 않습니다.

## 배포 방법 (관리자용)

새 버전은 비공개 소스 저장소의 배포 스크립트로만 올립니다. 이 저장소에 직접 파일을 올리지 않습니다.

1. **기능 병합** — 소스 저장소에서 기능 PR을 병합합니다.
2. **버전 올리기** — `scripts/release.sh bump X.Y.Z`가 앱 버전(세 곳)을 바꾼 PR을 만듭니다. 검토 후 병합합니다.
3. **내보내기** — main에서 `scripts/release.sh publish "<릴리스 노트>"`를 실행합니다. 스크립트가 차례로:
   1. 작업 트리가 깨끗하고 원격과 같은지, 같은 버전 릴리스가 없는지 확인
   2. 전체 테스트 실행
   3. 앱 빌드 (빌드 결과에 개인 경로가 남지 않았는지 검사)
   4. `Tid.app`을 `Tid_<버전>_<arch>.app.tar.gz`로 묶고 업데이트 서명 키로 서명
   5. `latest.json` (버전·노트·서명·내려받기 주소) 작성
   6. 이 저장소에 릴리스 `v<버전>`을 만들고 압축 파일과 `latest.json`을 올림
4. **확인** — 설치된 앱에서 "업데이트 확인"으로 새 버전이 받아지는지 봅니다.

지켜야 할 것:

- 버전은 항상 올립니다. 앱은 `latest.json`의 버전이 설치본보다 높을 때만 업데이트합니다.
- 릴리스 노트는 공개됩니다. 내부 경로·계정·비공개 계획을 쓰지 않습니다.
- 서명 키는 관리자 컴퓨터에만 있고 어떤 저장소에도 올리지 않습니다. 키를 잃으면 기존 설치본이 업데이트를 받지 못해(공개 키가 앱에 들어 있음) 새 키로 만든 버전을 한 번 손으로 다시 설치해야 하므로, 따로 백업합니다.
- 잘못된 버전을 냈으면 더 높은 버전으로 고쳐 다시 냅니다. 앱은 낮은 버전으로 내려가지 않아서, 릴리스를 지워도 이미 받은 앱은 그대로입니다.
